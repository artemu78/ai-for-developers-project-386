# Пользовательские сценарии

## Основной сценарий бронирования

1. Гость открывает публичную страницу календаря.
2. Выбирает тип встречи и один из доступных слотов.
3. Указывает имя и корректный email.
4. Подтверждает запись и видит сообщение с выбранным временем.
5. Переходит в календарь владельца и видит созданный звонок с типом встречи и контактами гостя.

Этот сценарий автоматизирован в `tests/e2e/booking.spec.ts`. Тест запускает настоящий
браузер, фронтенд и локальный HTTP-бэкенд и тем самым проверяет их совместную работу.

## Дополнительные сценарии

- занятый слот исчезает из списка доступных;
- API отклоняет повторное бронирование слота с ошибкой `409`;
- форма не отправляется без слота, имени или корректного email;
- владелец видит все будущие звонки и может создать новый тип встречи.

Конфликт бронирований дополнительно покрыт тестом `backend/app.test.mjs`.
